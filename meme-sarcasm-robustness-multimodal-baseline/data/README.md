# data/

| Folder | Contents | In Git |
|---|---|---|
| `raw/` | The exported dataset, read-only: `raw/MMSoc_Memotion_exported/{train,validation,test}/` with `metadata.csv` and `images/`. | No |
| `processed/` | Frozen-encoder feature caches: `processed/features/<name>/{train,validation,test}.pt` + `meta.json`. | No |
| `samples/` | A synthetic 4-row-per-split set in the dataset's layout, plus API request bodies. | Yes |

**Dataset.** Point `MEMOTION_DATA_DIR` at the dataset root, or unpack it into
`data/raw/MMSoc_Memotion_exported/`, which is used when the variable is unset. Never commit the
dataset, its zip or its image files (team README 9.4); `data/raw/` and `data/processed/` are
git-ignored. (Dataset-derived review evidence that the groups keep in Git on purpose is listed
under "Rules" in the main README.)

**Feature caches.** `python -m src.features.feature_engineering text|image` writes to
`data/processed/features/` by default. The shared cache zips (docs/Image_Cloud_Assets.md,
docs/Multimodal_Assets.md) contain a top-level `features/` folder: unpack them **into
`data/processed/`**:

```
unzip Image_Features_CLIP_ViTB32_20261006.zip -d data/processed/
unzip Text_Features_DistilBERT_20261016.zip   -d data/processed/
```

Checkpoints and run configs recorded before this layout name `features/<name>`. The loaders, the
trainer's records, `evaluate.py`, `results_report.py` and `check_tf32_emulation.py` (all through
`src/features/cache.py::resolve_features_dir`) and `reproduce_image.ps1` accept either location:
`features/<name>` falls back to `data/processed/features/<name>` and the other way round. So old
commands, shipped heads and archives unpacked at the repository root still work. Exceptions:
`scripts/compare_feature_caches.py` takes the two paths literally, and `notebooks/eda.ipynb` reads
only `data/processed/features/`.

| Cache (`data/processed/features/...`) | Encoder | Splits | Produced by |
|---|---|---|---|
| `20261006_code_fixes_validation_v2/` | CLIP ViT-B/32 `pooler_output`, CUDA (TF32) | train, validation | image group |
| `clip_vitb32_pooler_cpu/` | the same, CPU float32 | train, validation, test | multimodal group |
| `distilbert_first_token/` | DistilBERT `[CLS]` (`last_hidden_state[:, 0]`) | train, validation, test | multimodal group |
| `distilbert_mean_pooling/` | DistilBERT masked mean | train, validation, test | multimodal group |

**Samples.** `samples/synthetic_memotion/` is generated by `python -m scripts.make_synthetic_samples`:
invented captions and 64x64 drawings, no dataset content. It lets the loader, the predictor and the
API be smoke-tested without the dataset, e.g.

```
python -m src.serving.predictor --smoke --data_dir data/samples/synthetic_memotion \
    --train_config configs/train/multimodal_baseline.yaml      # untrained head: shapes only
curl -s -X POST localhost:8000/predict -H 'Content-Type: application/json' -d @data/samples/predict_request.json
```
